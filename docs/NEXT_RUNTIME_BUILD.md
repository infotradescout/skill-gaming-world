# Next Runtime Build — First Playable Vertical Slice

The next build should not attempt the complete commercial game. It should prove one honest loop from start to finish.

## Required player loop

1. Launch the game.
2. Choose Rammer, Ripper, or Maul.
3. Enter the generated arena.
4. Drive with keyboard or controller.
5. Use the selected robot’s weapon or ram action.
6. Fight one local training robot.
7. Reset the match without restarting the game.
8. Open a basic garage.
9. Change chassis, wheels, front armor, weapon, and paint.
10. Receive live mass and power totals.
11. Reject an overweight or disconnected design.
12. Save a valid blueprint.
13. Load that exact blueprint into the arena.

## Technical target

- Godot 4.7.1 stable.
- Import the GLB files generated by Blender.
- Use RigidBody3D with custom force-based drive behavior rather than VehicleBody3D.
- Use one server-owned robot root and separate active weapon body only when required.
- Create keyboard and gamepad actions.
- Run offline and local-host modes from the same match code.
- Add a headless server startup mode.
- Use WebSocket multiplayer for the browser-compatible path.
- Do not trust client physics, blueprint totals, damage, or match results.

## Acceptance proof

- Blender generator runs in Blender 5.2 LTS without manual scene repair.
- All expected output files exist.
- Godot imports every GLB without missing resources.
- Arena collision matches the visible boundary.
- Each starter bot spawns upright and can drive.
- Ripper’s spinner and Maul’s hammer have working server-owned states.
- Rammer can push another robot without tunneling through the floor or wall.
- The same valid blueprint reconstructs identically twice.
- At least one invalid mass build is denied.
- At least one unattached part build is denied.
- Two local processes can connect to one headless match server.
- The server decides position, collision, damage, clock, and result.
- No paid, prize, wager, cash, redemption, or Legal Play operation is added.
